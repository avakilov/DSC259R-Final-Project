What are we building?

This project analyzes major power outages across the continental United States, with a focus on predicting peak demand lost (in megawatts) at the onset of an outage — before full resolution data is available.

Understanding demand loss helps utility companies allocate resources, plan emergency responses, and communicate expected impact to customers in real time.

Target Variable
DEMAND.LOSS.MW — peak megawatts of demand lost
Problem Type
Regression — continuous real-valued output
Primary Metric
Root Mean Squared Error (RMSE) in MW
Model Progression
Random Forest baseline → LightGBM

Data Cleaning

How did we prepare the data?

Before analysis, we performed several cleaning steps to ensure only meaningful, valid data was used throughout the project.

Column Selection
Extracted columns relevant to our analysis: CAUSE.CATEGORY, OUTAGE.DURATION, CLIMATE.REGION, CLIMATE.CATEGORY, YEAR, CUSTOMERS.AFFECTED, and DEMAND.LOSS.MW.
Temporal Data Cleaning
Combined OUTAGE.START.DATE and OUTAGE.START.TIME into a singluar timestamp column called OUTAGE.START. Likewise, OUTAGE.RESTORATION.DATE and OUTAGE.RESTORATION.TIME were combined into OUTAGE.RESOTRATION.
Datatype Conversion
Using df.info() showed us that many columns that should be numeric were read in by default as objects. To correct this, we identified each object column that should have been numeric and manually converted them to the correct datatypes.
Invalid Value Replacement
Replaced negative or zero values in OUTAGE.DURATION with NaN — these are not valid durations. Missing categorical values were replaced with 'NaN' to avoid introducing bias.

Exploratory Data Analysis

What patterns exist in the data?

Univariate Analysis — Demand Loss

We conducted univariate analyses on multiple variables to explore variation in data within columns we're using in our model. Since we're aiming to predict demand loss, we want to see where data is centralized and outliers involved.

Demand Loss (MW) Distribution and Log Transformation

The `DEMAND.LOSS.MW` variable contains substantial missingness (approximately 44% of observations). Among the non-missing values, summary statistics indicate a mean of 375.9 MW and a median of 175.5 MW, with a maximum value of 41,788 MW. The large difference between the mean and median, combined with a very high skewness value (15.88), indicates extreme right skew and the presence of significant outliers. The raw distribution confirms this pattern, with most observations concentrated at relatively low demand loss levels and a long right tail driven by a small number of extreme events. After applying a log transformation, the distribution becomes more compressed and less skewed, reducing the influence of extreme values and producing a more stable distribution for modeling purposes.

Missingness Analysis

Is missing data random?

NMAR Analysis

We believe DEMAND.LOSS.MW is likely Not Missing At Random (NMAR). Utilities only generate a formal demand-loss estimate when an outage exceeds a significance threshold — meaning the missingness is tied to the unobserved value itself: small outages produce no estimate, so their values are absent precisely because they are small.

To make this MAR, we would want more information like knowing if demand-loss estimates are attempted when outages are below certain thresholds.

Hypothesis Testing

Do severe weather outages last longer?

We formally tested whether outages caused by severe weather have meaningfully longer durations than all other cause categories combined.

Null Hypothesis H₀
Mean outage duration for severe weather equals mean duration for all other causes.
Alternative Hypothesis H₁
Mean outage duration for severe weather is greater than for other causes.
Test Statistic & Method
T = mean(Durationsevere) − mean(Durationother)
Permutation test with 10,000 shuffles. P-value = proportion of permuted statistics ≥ observed.

Prediction Problem

What are we predicting — and why?

We frame our core task as a regression problem: given information known at the moment an outage is first reported, predict peak demand lost (DEMAND.LOSS.MW) before full resolution data is available.

Response Variable
DEMAND.LOSS.MW
Peak megawatts of demand lost. Predicting this helps utilities assess severity and dispatch resources before an outage is resolved.
Problem Type
Regression — continuous real-valued output. No natural class boundary exists for demand loss, making classification inappropriate.
Why RMSE over MAE?
RMSE penalizes large errors more heavily than MAE — appropriate here because underestimating a 2,000 MW loss is far more consequential than underestimating a 50 MW loss. RMSE is also expressed in the same unit as the target (MW), keeping results directly interpretable. R² is reported as a secondary variance indicator.

Features & Time-of-Prediction Justification

All features are observable at the moment an outage is first reported — no post-event information is used during training.

Modeling Approach

Baseline Model

Our baseline is a Random Forest Regressor built in a single sklearn Pipeline: a ColumnTransformer one-hot encodes CAUSE.CATEGORY and passes numeric features through, feeding directly into the forest. Rows with missing target values are imputed with the training median; the test set contains only observed demand-loss rows.

Is this a good model?
This is a fair model. An R² of 0.13 means the baseline outperforms predicting the mean, but not by much. The RMSE of ~1528 MW is extremely large relative to the median demand loss (~175 MW), and the negative CV R² during grid search confirms that five features with no target transformation are insufficient to capture the highly skewed distribution of DEMAND.LOSS.MW.
Final Model

LightGBM Regressor

The final model uses LightGBM, a gradient-boosted tree framework with leaf-wise growth that handles mixed feature types natively and is robust to the heavy right-skew of our target. We also trialled a Keras neural network and XGBoost; LightGBM produced the best generalization.

Key Feature Improvements

log₁p Target Transform
DEMAND.LOSS.MW has skewness ≈ 15.9. Predicting log(1 + MW) reframes the task as estimating order of magnitude, which the available features can predict far more reliably than raw MW values.
Full Feature Set (53 cols)
All 11 categorical columns (state, NERC region, climate region, climate category, etc.) are one-hot encoded; all 42 numeric columns use median imputation — giving the model economic, demographic, and geographic context absent from the baseline.
Time-Aware Train / Test Split
Outages from the latest ~25% of years form the test set; earlier years are used for training. This better mimics real deployment (predicting future outages) and prevents temporal leakage.

Hyperparameters

Selected configuration
learning_rate = 0.02  ·  num_leaves = 63  ·  subsample = 0.8  ·  colsample_bytree = 0.8  ·  reg_lambda = 1.0  ·  early stopping (patience = 200 rounds on validation MAE)

Early stopping on a held-out validation set acts as a continuous search over tree count, while row/column subsampling reduces variance on this noisy target.

Why the improvement
Log-transforming the target lets the model predict the scale of demand loss — a learnable signal — rather than exact MW values dominated by extreme outliers. Adding 48 features (economic, demographic, geographic) gives the model the context needed to distinguish a 100 MW event from a 10,000 MW one. The raw-space RMSE is higher than the baseline because the time-based test split contains harder, later-year outages; the 38% MAE reduction reflects genuine accuracy gains.
