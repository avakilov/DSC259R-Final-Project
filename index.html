What are we building?

This project analyzes major power outages across the continental United States, with a focus on predicting peak demand lost (in megawatts) at the onset of an outage — before full resolution data is available.

Understanding demand loss helps utility companies allocate resources, plan emergency responses, and communicate expected impact to customers in real time.

Target Variable
DEMAND.LOSS.MW — peak megawatts of demand lost
Problem Type
Regression — continuous real-valued output
Primary Metric
Root Mean Squared Error (RMSE) in MW
Model Progression
Random Forest baseline → LightGBM
Dataset

Data Cleaning

How did we prepare the data?

Before analysis, we performed several cleaning steps to ensure only meaningful, valid data was used throughout the project.

Column Selection
Extracted columns relevant to our analysis: CAUSE.CATEGORY, OUTAGE.DURATION, CLIMATE.REGION, CLIMATE.CATEGORY, YEAR, and CUSTOMERS.AFFECTED.
Empty Row Removal
Dropped rows where all values were missing so only meaningful data is used for analysis.
Grouped Aggregation
Grouped by CLIMATE.REGION, CAUSE.CATEGORY, and CLIMATE.CATEGORY, then dropped subcategory groups with no data using dropna(how='all').
Invalid Value Replacement
Replaced negative or zero values in OUTAGE.DURATION with NaN — these are not valid durations. Missing categorical values were replaced with 'NaN' to avoid introducing bias.

Hypothesis Testing

Do severe weather outages last longer?

We formally tested whether outages caused by severe weather have meaningfully longer durations than all other cause categories combined.

Null Hypothesis H₀
Mean outage duration for severe weather equals mean duration for all other causes.
Alternative Hypothesis H₁
Mean outage duration for severe weather is greater than for other causes.
Test Statistic & Method
T = mean(Durationsevere) − mean(Durationother)
Permutation test with 10,000 shuffles. P-value = proportion of permuted statistics ≥ observed.

Strong statistical evidence that outage duration depends on cause category. This motivates using cause-related variables as features in our prediction model.

Prediction Problem

What are we predicting — and why?

We frame our core task as a regression problem: given information known at the moment an outage is first reported, predict peak demand lost (DEMAND.LOSS.MW) before full resolution data is available.

Response Variable
DEMAND.LOSS.MW
Peak megawatts of demand lost. Predicting this helps utilities assess severity and dispatch resources before an outage is resolved.
Problem Type
Regression — continuous real-valued output. No natural class boundary exists for demand loss, making classification inappropriate.
Why RMSE over MAE?
RMSE penalizes large errors more heavily than MAE — appropriate here because underestimating a 2,000 MW loss is far more consequential than underestimating a 50 MW loss. RMSE is also expressed in the same unit as the target (MW), keeping results directly interpretable. R² is reported as a secondary variance indicator.

Features & Time-of-Prediction Justification

All features are observable at the moment an outage is first reported — no post-event information is used during training.

Why each feature is known at prediction time
MONTH / YEAR — recorded the instant the outage event begins.
CAUSE.CATEGORY — identified by operators at or shortly after outage onset (e.g., "severe weather" is apparent immediately).
RES.SALES — regional residential electricity sales; a pre-existing characteristic of the affected area, independent of any specific outage.
PCT_WATER_TOT — static geographic property of the state, fully known in advance.
Modeling Approach

Baseline Model

Our baseline model is a Random Forest Regressor. This ensemble model captures nonlinear relationships between economic, climate, and demographic variables and outage severity.

Train / Test Split
80% / 20%
Evaluation Metrics
RMSE and R²
Feature Engineering
Log-transform + standardization

We improved the baseline by using cross-validation for more reliable performance and tuning hyperparameters with GridSearch to optimize accuracy. We also analyzed feature importance to better understand the key drivers of outage severity.

Intermediate Model

XGBoost Regressor

We trained an XGBoost Regressor as an additional boosting-based model to compare with the Random Forest baseline. XGBoost builds decision trees sequentially, allowing each new tree to correct the errors of previous trees — making it effective for capturing more complex nonlinear relationships in the outage data.

Train / Test Split
80% / 20%
Evaluation Metrics
MAE, RMSE, and R²
Feature Engineering
Log-transform + standardization

On the log-transformed target space, XGBoost improved substantially over the baseline model and demonstrated strong predictive performance.

Final Model

LightGBM Regressor

We trained a LightGBM Regressor as our final model. LightGBM is a gradient boosting framework optimized for fast and efficient learning on structured tabular data. Its leaf-wise growth strategy allows it to capture highly complex patterns while maintaining strong computational efficiency.

Train / Test Split
80% / 20%
Evaluation Metrics
MAE, RMSE, and R²
Feature Engineering
Log-transform + standardization

Among all models tested, LightGBM achieved the best overall performance and was selected as the final model for outage severity prediction.

Fairness Analysis

Does the model perform equally across seasons?

We evaluated the fairness of our final LightGBM model by comparing its performance across two seasonal groups: Spring/Fall and Summer/Winter. The goal was to test whether the model systematically performed worse for one group than the other on the held-out test set.
